What Is Cloud Computing?

Cloud computing is the on-demand delivery of computing services—such as servers, storage, databases, networking, software, and analytics—over the internet with pay‑as‑you‑go pricing.

Key characteristics
  • On-demand self-service – provision resources in minutes from a console or API.
  • Broad network access – available over the internet from many device types.
  • Resource pooling – shared multi-tenant infrastructure with isolation.
  • Rapid elasticity – scale up and down with demand instead of fixed capacity.
  • Measured service – pay only for what you use, with fine‑grained metering.
From data centers to cloud
  • Traditional on‑premises: upfront CapEx, manual provisioning, long procurement cycles.
  • Cloud: shift to OpEx, API‑driven provisioning, global reach in minutes.
  • Abstracts hardware; lets teams focus on architectures, data, and applications.
For students

Think of the cloud as programmable infrastructure: every server, network, and storage system becomes an API you can script, automate, and compose into resilient distributed systems.

Why Do We Need Cloud Computing?

Beyond buzzwords, the cloud changes how we design, build, and operate software systems, especially at scale.

Agility & speed
  • Provision experiments in minutes instead of waiting weeks for hardware.
  • Iterate on architectures quickly; tear down when not needed.
  • Supports DevOps, CI/CD, and rapid innovation cycles.
Scalability & reliability
  • Scale from a few users to millions without redesigning hardware.
  • Leverage managed services with built‑in high availability and SLAs.
  • Global infrastructure enables low‑latency, multi‑region deployments.
Cost & focus
  • Move from capital expenditure to usage‑based operating expenditure.
  • Avoid undifferentiated heavy lifting: power, cooling, racking, patching.
  • Focus student projects on design, data, and algorithms—not hardware logistics.

Cloud Deployment Models

How infrastructure is owned and exposed drives security, control, and scalability trade‑offs.

Public cloud
  • Shared infrastructure operated by providers like AWS, Azure, GCP.
  • Elastic capacity, global reach, rich managed services.
  • Typical choice for startups, web apps, analytics, and experimentation.
Private cloud
  • Cloud principles applied inside a single organization.
  • More control, customized security; higher management overhead.
  • Often built with OpenStack, VMware, or on‑premises AWS/Azure stacks.
Hybrid cloud
  • Combines on‑premises and public cloud resources.
  • Useful for gradual migrations, data residency, or legacy systems.
  • Requires robust networking, identity, and governance patterns.
Multi‑cloud
  • Uses services from multiple public cloud providers.
  • Can reduce vendor lock‑in or optimize for specific capabilities.
  • Increases complexity in architecture, operations, and skills.

Cloud Service Models

Service models define how much of the stack you manage versus the provider.

Infrastructure as a Service (IaaS)
  • Virtual machines, storage, and networking exposed as APIs.
  • You manage OS, runtime, data, and applications.
  • Examples: AWS EC2, EBS, VPC, Azure VMs, GCP Compute Engine.
Platform as a Service (PaaS)
  • Managed runtimes and databases; deploy code, not servers.
  • Provider handles OS, patching, scaling, and high availability.
  • Examples: AWS Elastic Beanstalk, AWS Lambda, RDS, Azure App Service.
Software as a Service (SaaS)
  • Complete applications delivered over the internet.
  • Users configure and consume; provider manages everything else.
  • Examples: Gmail, Salesforce, Office 365, many AI‑powered SaaS tools.

AWS at a Glance

We will briefly tour the AWS Management Console and map its structure to core architectural concepts.

Global infrastructure concepts
  • Regions – separate geographic areas (e.g., ap-south-1).
  • Availability Zones – isolated data centers within a region for high availability.
  • Edge locations – global points of presence for caching and content delivery.
  • Designing for reliability means using multiple AZs and sometimes multi‑region.
Console walkthrough (demo script)
  1. Sign in to AWS console; show region selector and search bar.
  2. Navigate to IAM, EC2, S3, Lambda dashboards to show service tiles.
  3. Highlight "Services" and "Recently visited" for quick navigation.
  4. Show account details, billing, and support menus (without exposing secrets).

AWS Identity and Access Management (IAM)

IAM controls who can do what on which AWS resources. It is foundational for any serious AWS usage.[web:15]

Core IAM concepts
  • Users – long‑lived identities for people or applications.
  • Groups – collections of users sharing policies.
  • Roles – identities assumed by AWS services or external identities.
  • Policies – JSON documents that define allowed or denied actions.
Demo storyboard: IAM
  1. Open IAM in console; show users, roles, and policies sections.
  2. Create a demo IAM user with programmatic access and limited S3 permissions.
  3. Attach a managed policy (e.g., AmazonS3ReadOnlyAccess) and explain least privilege.
  4. Highlight CloudShell / AWS CLI usage with IAM credentials (conceptually; avoid exposing secrets).

Amazon EC2 – Virtual Servers in the Cloud

EC2 lets you launch and manage virtual machines with different CPU, memory, and storage characteristics.[web:3][web:6][web:9]

Concepts
  • Instance types (t3.micro, m5.large, etc.) optimized for general, compute, memory, or GPU workloads.
  • AMI (Amazon Machine Image) defines OS and base software.
  • Key pairs for SSH access; security groups as virtual firewalls.
  • EC2 integrates with EBS volumes, IAM roles, and VPC networking.
Demo storyboard: EC2
  1. From console, navigate to EC2 and show dashboard metrics.
  2. Launch a small Linux instance (e.g., t2.micro) in a public subnet.
  3. Explain security group inbound rules (SSH/HTTP) and key pair usage.
  4. Optionally SSH in and deploy a simple web server or API.

Amazon S3 – Object Storage

S3 provides virtually unlimited, highly durable object storage for files, backups, data lakes, and static websites.[web:3][web:6][web:9]

Concepts
  • Data stored as objects inside buckets with globally unique names.
  • Designed for eleven 9s (99.999999999%) of durability.[web:9]
  • Multiple storage classes (Standard, Infrequent Access, Glacier) for cost optimization.
  • Fine‑grained access control using IAM policies and bucket policies.
Demo storyboard: S3
  1. Create a bucket with a region‑specific name.
  2. Upload sample files (images, JSON, logs) via console.
  3. Show object URL patterns and basic access control options.
  4. Optionally enable static website hosting and access via browser.

AWS Lambda – Serverless Functions

Lambda lets you run code without provisioning or managing servers. You pay only for compute time consumed.[web:3][web:6][web:9]

Concepts
  • Event‑driven: triggered by S3 uploads, API Gateway, queues, or schedules.
  • Supports multiple runtimes (Node.js, Python, Java, etc.).
  • Scales automatically with the number of events.
  • Integrates with IAM, VPC, and other AWS services.
Demo storyboard: Lambda
  1. Create a simple Lambda function (e.g., Node.js or Python) via console editor.
  2. Use a basic handler that logs the event and returns a JSON response.
  3. Invoke it from the console and show logs in Amazon CloudWatch.
  4. Optionally trigger it from S3 or an HTTP endpoint (API Gateway).

Terraform & Infrastructure as Code

Terraform lets you describe cloud infrastructure in declarative configuration files and provision it consistently across environments.

Why IaC?
  • Version‑control infrastructure alongside application code.
  • Repeatable, documented environments for dev, test, and production.
  • Automated provisioning and teardown reduces human error.
  • Enables review, collaboration, and testing of infrastructure changes.
Terraform on AWS – demo storyboard
  • Write a minimal Terraform configuration that creates an S3 bucket or EC2 instance.
  • Run terraform init, plan, and apply to provision resources.
  • Show how state tracks infrastructure and how destroy cleans it up.
  • Discuss modules and reusable patterns for larger systems.

AI & ML on AWS – Typical Use Cases

AWS provides both pre‑built AI services and flexible ML platforms to integrate intelligence into applications.

Managed ML platform
  • Amazon SageMaker for building, training, and deploying ML models at scale.
  • Supports Jupyter notebooks, distributed training, and managed endpoints.
  • Useful for research projects and custom ML workflows.
Pre‑built AI APIs
  • Services for vision, speech, text, personalization, and forecasting.
  • Integrate AI without training models from scratch.
  • Combine with Lambda, S3, and API Gateway for full workflows.
Example projects for students
  • Serverless image classifier using S3, Lambda, and an AI API.
  • Chat or Q&A interface backed by vector search and AI services.
  • Analytics pipeline from data ingestion to dashboards with embedded ML.
